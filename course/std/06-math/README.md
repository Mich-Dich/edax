# Std lesson 6: Vectors, rectangles and colours (`std::math`)

`std::math` holds the small value types that UI and 2-D rendering code passes around all day: vectors, rectangles and colours, plus a few easing functions. They're plain copy-type structs of `f32` with C layout, so an array of them can go to the GPU as it is. They're also a good example of library design in Edax: operators as methods, `@std::derive::formattable` for printing, and functions that never produce NaNs behind your back.

**You will learn:** `vec2` / `vec3` / `vec4` and their operators, `rect` and its half-open edges, `color` in sRGB and why derived shades are computed in OKLCH, contrast for readable text, and `lerp` / `smoothstep`.

**You will build:** the layout, hit testing, colours and highlight animation of a toolbar (`exercise.ed`).

Examples are in [`examples/`](examples); `python3 course/check.py s6 --examples` checks them. The module loads when a program names `std::math`; a namespace alias keeps the names short: `namespace m = std::math;`.

## 1. Vectors

| Type | Fields | Methods |
|---|---|---|
| `vec2` | `x`, `y` | `splat`, `dot`, `length`, `length_squared`, `normalized`, `perpendicular`, `abs`, `min`, `max`, `lerp`; `+ - *` (by a vector or an `f32`), `/` (by an `f32`), unary `-`, `==` |
| `vec3` | `x`, `y`, `z` | `splat`, `dot`, `cross`, `length`, `normalized`, `lerp`; `+ - * /`, unary `-`, `==` |
| `vec4` | `x`, `y`, `z`, `w` | `splat`, `dot`, `lerp`; `+ - *`, `==` |

```edax
m::vec2 a = m::vec2{ .x = 3.0, .y = 4.0 };
m::vec2 b = m::vec2::splat(1.0);          // { 1, 1 }
a + b, a * 2.0, -a, a.length(), a.dot(b)
```

- Built like any struct (`m::vec2{ .x = 3.0 }`, the rest default to 0), so there are no constructor overloads to remember.
- `normalized()` of the zero vector is the zero vector, not NaNs: a single degenerate input can't poison a whole frame.
- `perpendicular()` turns 90° counter-clockwise in a y-up frame: `(x, y) → (-y, x)`.
- They print as `std::math::vec2 { x: 4.0, y: 5.0 }` (generated by `@std::derive::formattable`); print the fields when you want something shorter.

Example: [`vectors.ed`](examples/vectors.ed).

## 2. Rectangles

`rect` is a top-left corner and a size (`x`, `y`, `width`, `height`), with **y pointing down**, as on screens.

| Make | Ask | Change |
|---|---|---|
| `rect{ .x, .y, .width, .height }` | `left`, `top`, `right`, `bottom` | `shrunk(d)` (never below size 0), `expanded(d)` |
| `rect::from_corners(a, b)` (any order) | `origin`, `size`, `center` | `translated(v)` |
| `rect::at(origin, size)` | `contains(p)`, `overlaps(r)`, `is_empty` | `intersection(r)` (size 0 when apart), `united(r)` |

**Edges are half-open:** the left and top edges are inside, the right and bottom edges aren't. So two buttons that share an edge never both contain the point on it, and a click can't hit two of them:

```edax
r.contains(r.origin())                              // true
r.contains(m::vec2{ .x = r.right(), .y = r.bottom() })   // false
```

Example: [`rects.ed`](examples/rects.ed).

## 3. Colours

`color` is **sRGB with straight alpha**, every channel in `[0, 1]`: what colour pickers, CSS and image files mean by a colour.

| Make | Use |
|---|---|
| `color::hex(0x4F7CFF)`, `hex_alpha(0x4F7CFF80)`, `rgb8(r, g, b)`, `rgba8` | `with_alpha(a)` |
| `color::white()`, `black()`, `transparent()` | `packed()`: bytes r, g, b, a with r in the lowest byte (`GL_RGBA` + `GL_UNSIGNED_BYTE`), so `0x4F7CFF` packs as `0xFFFF7C4F` |
| `color::from_oklch(c, alpha)` | `to_oklch()`, `mix(to, t)`, `lighter(amount)` |
| | `luminance()` (WCAG 2), `contrast(other)`: 1 to 21 |

### Why OKLCH for shades

A hover colour, a pressed colour, a disabled colour: themes derive them from one base colour. In HSL, "10 % lighter" looks very different for yellow and for blue, because HSL's lightness isn't how eyes see brightness. **OKLCH** (`l` lightness, `c` chroma, `h` hue in degrees) is built so that equal steps of `l` look equal. So the recipe is:

```edax
m::oklch o = base.to_oklch();
m::color hover = m::color::from_oklch(m::oklch{ .l = o.l + 0.08, .c = o.c, .h = o.h }, base.a);
```

`from_oklch` keeps lightness and hue of a colour that falls outside sRGB and lowers its chroma until it fits, instead of clipping channels (which would shift the hue). `mix` works in OKLab too, so the middle of two equally light colours is equally light.

### Readable text

`a.contrast(b)` is the WCAG contrast ratio, from 1 (identical) to 21 (black on white). 4.5 is the usual minimum for body text, 3 for large text. Choosing white or black text per background is one comparison:

```edax
if (white.contrast(bg) >= black.contrast(bg)) { white } else { black }
```

Example: [`colors.ed`](examples/colors.ed).

## 4. Easing

| Function | Gives |
|---|---|
| `m::lerp(a, b, t)` | `a + (b - a) * t`: straight blend |
| `m::smoothstep(e0, e1, x)` | 0 below `e0`, 1 above `e1`, an S-curve between (slow start, slow end) |
| `v.lerp(w, t)`, `c.mix(d, t)` | the same for vectors and colours |
| `m::pi` | a `compile_time f32` |

Animating with `smoothstep(0.0, 1.0, t)` as the blend factor of a `lerp` is the quickest way to make movement look less mechanical.

Example: [`easing.ed`](examples/easing.ed).

## C++ → Edax at a glance

| C++ (glm and friends) | Edax |
|---|---|
| `glm::vec2(3, 4)` | `m::vec2{ .x = 3.0, .y = 4.0 }` |
| `glm::vec2(1)` | `m::vec2::splat(1.0)` |
| `glm::normalize(v)` (NaN for zero) | `v.normalized()` (zero for zero) |
| `glm::mix(a, b, t)` | `m::lerp(a, b, t)`, `v.lerp(w, t)` |
| `glm::smoothstep` | `m::smoothstep` |
| `SDL_Rect` / `QRectF` | `m::rect` |
| `M_PI` | `m::pi` |

(The second click lands in the 4-pixel gap; the third is below the inner area, which the padding shrank to y < 40.)

<details>
<summary>Hint 1: <code>row</code></summary>

`m::rect inner = area.shrunk(padding);`. With `n` buttons there are `n - 1` gaps: `width = (inner.width - gap * (n - 1)) / n`, and button `i` starts at `inner.x + i * (width + gap)`. Convert `usize` to `f32` with `cast::round<f32>`.
</details>

<details>
<summary>Hint 2: <code>hit</code>, <code>text_on</code>, <code>hover</code></summary>

`hit` returns `std::some(i)` for the first `buttons[i].contains(p)`. `text_on` compares `white.contrast(background)` with `black.contrast(background)`. `hover` is the OKLCH recipe from section 3, with `(o.l + amount).min(1.0)`.
</details>

<details>
<summary>Hint 3: the highlight</summary>

`f32 t = m::smoothstep(0.0, 1.0, cast::round<f32>(step) / 2.0);` then `from.lerp(to, t)`.
</details>

## Try this afterwards

1. Click exactly at `(buttons[0].right(), 20.0)`. Which button is hit?
2. Make `hover` add 0.5 to the lightness. What does a dark background turn into?
3. Replace the OKLCH hover by `bg.mix(m::color::white(), 0.1)`. Compare the luminance gain on the two backgrounds.
4. Lay out 0 buttons.

<details>
<summary>What happens</summary>

1. None: the right edge belongs to the area to the right of it, which here is the gap.
2. A light tint of the same hue (`.min(1.0)` keeps it in range), not grey or a different colour.
3. It still gets lighter, but by visibly different amounts on dark and light backgrounds; the OKLCH version lifts both by the same perceived step.
4. An empty darray, and no panic: the width divides by `0.0`, which for floats is infinity, not a panic (only *integer* division by zero panics). Nothing uses the width because the loop runs zero times, but a guard `if (count == 0)` says so explicitly.
</details>

## Recap

- Vectors, rects and colours are copy-type `f32` structs with operators, built with designated fields.
- `rect` is y-down with half-open edges; `normalized()` never makes NaNs.
- `color` is sRGB with straight alpha; derive shades in OKLCH; `contrast` picks readable text.
- `lerp` + `smoothstep` for motion.
