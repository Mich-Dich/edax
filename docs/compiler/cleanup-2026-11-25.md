# Compiler cleanup sweep (2026-11-25)

## How it was checked

- The build has no warnings under strict flags. All 165 unit tests pass.
- An ASan/UBSan build (`build-asan/`) found no memory errors in:
  - the feature suite (16/16) and the run/ and check/ action tests
  - all UI examples
  - insights, explain-checks, simd-report and typed
- Fuzzing found no crashes:
  - about 1,900 syntax mutations of the test programs through `edaxc check`
  - about 480 semantic mutations through codegen
- A `callgrind` profile of `edaxc build` on `std_ui_tables.ed` (a large std::ui program) showed where the time goes.

Action tests that fail in the cloud copy (build/, cli/, examples/) need fixtures that aren't there. The std_ui_* tests can hit the 20 s test timeout under ASan when the machine is loaded; each one passes when run alone.

## Soundness bugs fixed (check.cpp)

| Accepted before, now an error | Fix |
|---|---|
| `this.view[i].n = 1`, `s[0].bump()`, `touch(mut s[0])`, `mut cell& r = s[0]` on a `std::span<T>` (not `span<mut T>`) | Indexing a container whose `operator[]` only gives immutable references makes the element immutable. The new note says to use `std::span<mut T>` / `as_mut_span()`. |
| `mut u32& r = x;` with `x` immutable (also `c.n`) | `require_mut_reference` on `mut T&` locals |
| `holder{ .r = x }` with a `mut u32& r` field | the same check on struct-literal fields |
| `mut u32& pass(u32& x) { return x; }` | the same check on `return` |
| `mut u32& leak() { return this.v; }` in a non-mut method | the same check (E4021) |

Regression tests: `tests/action/check/immutable_span_elements.ed` and `tests/action/check/mut_reference_binding.ed`.

## Speed

| Change | Effect |
|---|---|
| Object-cache keys (and ThinLTO units) are hashed and passed to workers as **bitcode**, not printed IR text. `EDAX_CACHE_DUMP` still writes `.ll`. | Module::print was 39% of a warm build. 8.28 → 5.84 G instructions, about 3.1 s → 1.15 s warm. |
| `name_constants_by_content` hashes constants structurally (raw data bytes, APInts, operands) instead of printing them. | It was 3.4% here, and it grew with the size of constant data (embedded assets). |
| Parser lookaheads return `false` instead of throwing; `fail_unexpected` doesn't format a message while speculating. | Fewer exceptions on the hot path; about 5.58 G instructions in total |

Incremental builds still work: adding a string to `main` recompiles 2 of 83 units.

## Open items (not changed)

- **Unknown `std::` names are unchecked "external" types.** `std::vectr<u32> xs = default;` passes `edaxc check` and only fails at codegen with E6001. A loop over it isn't checked either. Consider an error for `std::` names that the std modules don't declare (keeping a list of the deliberate external ones).
- **`unit_module` clones the whole module once per unit** (CloneModule is about 22% of a warm build). Hashing a unit's functions without cloning, or extracting only what a unit references, would make cached builds much faster.
- **The compile-time evaluator signals "unknown" with an exception.** That is about 1.5% of the build, mostly `lower()` of template-dependent types in generic bodies.
- **Goldens of the std_ui tests contain std line numbers**, so any edit to ui.ed shifts them. Run `--update` and review.
- On a full checkout: run the whole action suite against `build-asan` (ASan cmake line in ui-status.md).
